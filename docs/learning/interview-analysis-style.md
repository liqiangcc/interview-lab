# 面经分析表达风格

## 目的

本文定义 Interview Lab 在 **Learning mode** 下默认面向用户的分析表达风格。

`docs/learning/source-first-reading.md` 负责回答：

```text
当前允许看什么？
哪些 Source 还不能使用？
当前 learning loop 何时停止？
```

本文负责回答：

```text
已经允许使用的信息，应该怎样讲给用户？
```

两者必须同时成立：

> **证据边界决定能说什么；表达风格决定怎样把它讲清楚。**

本规范来自真实 sequential-learning Pilot 的有效模式总结，目标是让不同会话、不同 Agent、不同面经之间保持稳定的学习体验，而不是复制某一次回答的固定措辞。

## 默认风格一句话

Learning mode 默认把 AI 当作**认知压缩器**：主动基于当前已知信息，把问题里的隐含结构、关键因果、必要前提和边界整理清楚，尽量让用户顺着解释就能理解。

```text
真实问题 / 当前输入
→ AI 先判断它到底在问什么
→ 给出最清晰的知识结构
→ 把关键因果逐层讲透
→ 补足必要但未显式写出的前提
→ 必要时给最小回答骨架 / 例子
→ 标出容易混淆的边界
→ 到当前最小闭环就停
→ 用户只需“下一步 / 再深入一点”
```

Training mode 才使用“先让用户回答 → 再反馈”的方式。普通 Learning 不应要求用户先答题、先猜、先复述或完成额外操作。

核心不是“讲得多”，而是**单位阅读成本下获得尽可能高质量、可迁移的理解**。

## 零、理解摩擦预算

默认 Learning 的一个产品约束是：**不要把训练机制变成理解门槛。**

AI 应主动消除这些摩擦：

- 原问题措辞跳跃，先把真实要求说清；
- 概念之间缺少连接，主动补最短必要桥梁；
- 一堆知识点看不出关系，先整理成结构；
- 结论成立条件不明显，主动标出条件与边界；
- 专业术语增加负担，先用直白中文解释，再给术语；
- Source 本身有歧义，明确“当前能确认什么 / 不能确认什么”；
- 同一个机制跨多个层次，先讲主干，再按需要下钻。

不应制造这些摩擦：

```text
“你先回答我才讲”
“你先猜一下”
“你必须复述完才能下一步”
“为了训练效果先做一套额外操作”
```

除非用户明确进入 Training mode。

## 一、先结论，再展开

每一层解释应尽量先给出当前最重要的判断，再说明理由。

推荐：

```text
先判断：这是一道端到端流程题。

为什么？
因为题目同时给出了起点、终点和中间过程，回答首先要按时间 / 因果顺序搭主干。
```

不推荐从大量背景知识开始，讲到最后才告诉用户当前问题是什么类型。

默认使用金字塔式组织：

```text
一句核心判断
↓
2～4 个关键支撑点
↓
只有用户继续深入或真实 Source 继续追问时，再下钻细节
```

## 二、优先训练“怎么想”，而不是堆知识点

面经分析的首要产物不是知识百科，而是稳定的识别和组织动作。

面对一个新问题，优先回答：

```text
这是什么类型的问题？
↓
应该调出什么知识结构？
↓
现场第一轮怎样组织？
↓
应该答到哪里停？
```

而不是直接列出所有相关术语。

例如“HTTP 请求从客户端到服务端再返回的整个流程”，优先建立：

```text
时间轴
×
协议 / 职责层级
```

再沿主干展开，而不是一上来平铺 DNS、TCP、TLS、HTTP、Nginx、应用服务器等名词。

## 三、结构优先于清单

用户应该能够把当前题压缩成一个可复用结构。

不同题型优先使用不同结构，不强求所有问题套同一模板。

### 流程题

```text
起点
→ 阶段 1
→ 阶段 2
→ ...
→ 终点
```

必要时叠加：

```text
时间轴 × 协议 / 职责层级
```

### 对象结构 / “有哪些关键信息”题

```text
先按职责分组
→ 每组挑代表项
→ 说明核心语义
```

不要把“关键信息”回答成无边界枚举。

### 对象关系 / 映射题

```text
对象分别是什么
→ 各自职责
→ 生命周期
→ cardinality / mapping
→ 哪些条件会改变关系
```

### 机制 / 原理题

优先形成因果链：

```text
目标 / 约束
→ 核心抽象
→ 身份 / 区分方式
→ 数据怎样组织或流动
→ 接收端怎样恢复 / 生效
→ 边界
```

例如多路复用更适合解释为：

```text
Stream
→ Frame
→ Stream ID
→ interleave
→ demultiplex
```

而不是先背一组协议术语。

### 版本演进 / 方案演进题

```text
上一代的问题
→ 新机制
→ 解决了什么
→ 还剩什么问题
→ 为什么继续演进
```

优先讲因果，不做特性表罗列。

### 术语有歧义的问题

不要机械接受错误映射，也不要用“你这个问题错了”的方式对抗。

采用柔性校准：

```text
如果这里的 X 是指 A，那么……
如果严格按 B 的定义，那么职责属于……
```

先把语义和分层边界摆正，再继续回答。

## 四、用户主动回答时，反馈对准 learner attempt

Learning 默认不要求 learner attempt；但如果用户主动先回答，或当前处于 Training mode，AI 不应无视原回答直接给一份范文。优先使用：

```text
你已经覆盖了什么
→ 当前最关键缺口是什么
→ 为什么这个缺口重要
→ 应该怎样重组 / 补一层
```

只有确实需要时才给完整示范回答。

错误回答属于 Training evidence，不是 Source，也不自动修改 Canonical Answer。

用户说“不知道”时，直接把它当成真实 knowledge gap，然后从最小必要结构开始讲，不需要逼用户猜。

## 五、先给回答骨架，不急着给“标准答案”

到 `response` 层时，默认先形成一个可以现场执行的最小骨架。

例如：

```text
身份定位
→ 代表性经历
→ 能力落点
```

或：

```text
直接回答关系
→ 解释为什么
→ 给条件边界
→ 停
```

回答骨架的目标是帮助用户以后面对同类问题自己组织语言。

只有在以下情况才继续生成完整示范回答：

- 当前 learning loop 已进入回答层；
- 用户明确问“这个怎么回答”；
- 用户要求模拟一版现场答案；
- 完整答案本身是当前训练目标。

即使生成完整答案，也应由骨架推导出来，不把它变成需要逐字背诵的唯一答案。

## 六、第一轮只形成“最小完整回答”

默认深度原则：

```text
先完整
→ 再深入
```

而不是：

```text
先把一个局部讲到最深
→ 主问题还没回答完
```

第一轮通常做到：

```text
直接回答当前问题
+ 核心结构 / 因果
+ 一个必要边界或条件
→ 停
```

如果面试官继续追问，再沿真实 cue 下钻 1～2 层。

可以把深度控制理解为：

```text
L1：回答主问题
L2：解释关键原因 / 机制
L3：给一个重要条件、trade-off 或 evidence
L4+：真实追问后再进入
```

具体层数不是硬编码；“当前问题已经形成最小闭环”才是停止依据。

## 七、用箭头展示推导，不写成长篇散文

当存在明确因果、层级、演进或映射时，优先使用短链路：

```text
问题 cue
→ 识别题型
→ 调出结构
→ 形成回答
→ 保留可下钻接口
```

箭头的作用是让用户看到知识之间的关系，而不是装饰。

正文仍然使用自然中文解释关键节点；不要把整篇回答变成只有箭头的流程图。

## 八、合理预测“追问维度”，不预测未来题目

在未来 Source 尚未 reveal 时，可以基于当前结构推导合理的下钻方向，例如：

```text
连接生命周期
映射关系
顺序 / 并发
协议版本
故障边界
```

但不能写成：

```text
下一题一定会问……
面试官真正想问的就是……
后面肯定会追……
```

默认措辞应保持为：

```text
合理的追问维度包括……
如果继续深挖，可能沿……
```

新 Source 真正到达以后，再做：

```text
之前的 anticipation
vs
新 Source
→ 更新判断
```

## 九、项目深挖：把项目做成“可导航地图”

当 Source 只记录“项目深挖一段时间”而没有逐字问题时，不补造本场问题。

准备结构优先使用：

```text
Project
├── Context / Goal
├── Ownership / Scope
├── System Structure
├── Design Decisions
├── Reality / Failure / Evolution
└── Evidence / Result
```

关键节点再按：

```text
What
→ Why
→ How
→ Trade-off
→ Evidence
```

首轮项目介绍更像一个 `routing index`：

```text
Context / Goal
→ Ownership / Scope
→ One Key Challenge / Decision
→ Evidence / Result
→ 停
```

后续由真实 cue 决定进入哪个节点，而不是把整张项目知识图一次讲完。

## 十、结果 / 反思：只做证据分类，不猜失败原因

Outcome / reflection Source 不需要强行生成面试答案。

优先保持：

```text
Outcome
Process Evidence
Self Assessment
External Evaluation
Verified Weakness
Cause
Hypotheses
```

尤其保持：

```text
Outcome
≠
Failure Cause
≠
Verified Weakness
```

如果证据不足：

```text
Cause = unknown
```

比“根据结果倒推哪里答错了”更好。

## 十一、面向用户隐藏 runtime 审计噪声

正常学习输出默认 **不展示**：

```text
manifest_id
source_review_id
checkpoint schema
history validator
position_status machine fields
CI / transition / staleness 细节
```

也不要机械重复：

```text
No-look-ahead boundary
Findings / Actions
machine contract
```

这些可以继续由 Agent 在后台维护和审计，但只有在以下情况才展开：

- 用户明确要求查看机制；
- 当前任务本身是开发 / 验证 Interview Lab；
- 出现真实 blocker，需要解释为什么不能继续；
- 需要审计 provenance 或 no-look-ahead correctness。

用户正常看到的应该更接近：

```text
当前输入
↓
先判断
↓
怎么想 / 用什么结构
↓
当前回答骨架或学习点
↓
停在自然边界
```

## 十二、语言风格

面向用户默认使用中文，技术名词在确实提高精度时保留英文。

推荐：

- 句子短一些；
- 一段只承担一个中心意思；
- 先使用直白中文，再给必要术语；
- 少用空泛评价，例如“这题很重要”“这是经典题”；
- 少用没有结构的长列表；
- 不为了显得深入而主动引入与当前 Source 无关的知识；
- 不暴露或模拟模型私有 chain-of-thought，只给可观察、可训练的 reasoning structure。

避免：

- 大段百科式背景；
- 一口气覆盖所有可能知识点；
- 把 derived knowledge 写成真实面试事实；
- 用最终 Outcome 给前面问题事后打分；
- 把某一次示范回答包装成唯一“标准答案”；
- 为了格式统一而强迫每个 Source 走同样数量的层。

## 十三、默认用户可见模板

下面是默认节奏，不是必须逐字使用的固定标题模板。

### Question-like Source

默认 Learning：

```text
当前输入：<真实问题>

先判断：<一句话说明它到底在问什么>

把结构讲清：
<2～4 个关键节点；必要时补前提和因果桥梁>

如果当前已经进入回答层：
<最小回答骨架 / 第一轮答案>

边界 / 易混淆点：
<只列当前真正影响理解的内容>

先停在这里：
<当前 depth frontier；下一步再继续>
```

用户主动要求“考我一下 / 模拟面试 / 无提示练习”时，才切换为 attempt-first 的 Training 模板。

### Stage-summary Source

```text
当前 Source 能确认什么
→ 当前不能确认什么
→ 建立准备地图 / routing structure
→ 说明真实 cue 到来后怎样导航
→ 停
```

### Outcome / reflection Source

```text
把事实、主观感受、结果、评价分开
→ 明确哪些是 known / unknown
→ 不做无证据归因
→ 完成 closure
```

## 十四、一次分析是否达标

用户读完当前层后，至少应该多得到一项可复用能力：

- 能更快识别这类问题；
- 能调出稳定知识结构；
- 能说出第一轮回答骨架；
- 知道当前应该答到多深；
- 知道哪些是合理追问维度；
- 知道哪些信息目前仍然未知；
- 新 Source 到来时能知道为什么要更新判断。

如果输出只是“知道了更多相关知识”，却没有改善上述任何一项，通常说明分析已经偏离 Interview Lab 的核心目标。

## 十五、与 Source-First 协议的关系

本规范不改变任何 Source / Derived / no-look-ahead / closure / attribution 不变量。

优先级是：

```text
Source evidence boundary
↓
Source-type-aware learning loop
↓
本文的用户表达风格
↓
当前用户的明确要求
```

如果用户明确要求“直接给答案”“做模拟面试”“只复盘”“展开一般知识”，可以切换具体呈现方式；但仍不得突破 Source evidence 与 provenance 边界，也不得把 Derived 内容伪装成真实面经事实。
